Price and stock from one store with Playwright: read the page's structured data before writing selectors

2026-11-10

A GitHub issue opened on 09.11.2026 scopes the first piece of a price tracker: open one pilot store's website, read the price and stock of 5 products with Playwright, print the results, and only then extend to more stores. That's a sensible first step. Here's how I'd write it so the 5-product version keeps working when you add a second store, and where it will still break.

The short version: most product pages already describe their price and availability in machine-readable form, for search engines. Read that first, and only fall back to CSS selectors when it's missing.

Check what the store already publishes (5 minutes, no code)

Open one product page, view the source (not the inspector, the raw source) and search for application/ld+json. On most shop systems you'll find a schema.org Product block with an offers object that looks like this:

{
  "@type": "Product",
  "name": "...",
  "sku": "...",
  "offers": {
    "@type": "Offer",
    "price": "49.90",
    "priceCurrency": "CHF",
    "availability": "https://schema.org/InStock"
  }
}

Two shop systems also have public JSON you can open in the browser:

  • Shopify: add .js to the product URL (/products/<handle>.js). You get the variants with price in cents (an integer) and available as true/false. /products/<handle>.json exists too, with prices as strings like "49.90".
  • WooCommerce: /wp-json/wc/store/v1/products?slug=<slug> (the Store API, no key needed unless the shop has switched it off). Prices are strings in minor units, with currencyminorunit telling you where the decimal point goes, plus isinstock.

If the pilot store is a partner rather than a site you're watching from outside, ask them first. Many stores already generate a product feed (for Google Shopping, for example) with price and availability for every product, and that beats any scraper.

The script

This uses Playwright as the issue asks, reads JSON-LD first, falls back to selectors you set per store, respects robots.txt and waits between pages. It prints one line per product and appends to a CSV so you have history from day one.

# pip install playwright && playwright install chromium
import csv, json, time
from datetime import datetime, timezone
from urllib import robotparser
from urllib.parse import urlparse
from playwright.sync_api import sync_playwright, TimeoutError as PWTimeout

UA = "price-tracker-pilot/0.1 (+https://your-project-page.example)"
DELAY_S = 5
PRODUCTS = [
    "https://store.example/products/item-1",
    # ... 5 product URLs
]
# Only used when the page has no usable JSON-LD. Fill in after looking at one page.
FALLBACK = {"price": ".product-price", "stock": ".stock-status"}

_robots = {}
def allowed(url):
    host = urlparse(url)
    base = f"{host.scheme}://{host.netloc}"
    if base not in _robots:
        rp = robotparser.RobotFileParser(base + "/robots.txt")
        rp.read()
        _robots[base] = rp
    return _robots[base].can_fetch(UA, url)

def walk(node):
    """Yield every dict in a JSON-LD tree (handles @graph, lists, nesting)."""
    if isinstance(node, list):
        for n in node:
            yield from walk(n)
    elif isinstance(node, dict):
        yield node
        for v in node.values():
            yield from walk(v)

def is_type(node, name):
    t = node.get("@type")
    return name in (t if isinstance(t, list) else [t])

def from_jsonld(blocks):
    for raw in blocks:
        try:
            data = json.loads(raw)
        except json.JSONDecodeError:
            continue
        for node in walk(data):
            if not is_type(node, "Product"):
                continue
            offers = node.get("offers") or {}
            offers = offers if isinstance(offers, list) else [offers]
            for o in offers:
                price = o.get("price", o.get("lowPrice"))
                if price is None:
                    continue
                avail = str(o.get("availability", "")).rstrip("/").rsplit("/", 1)[-1]
                return {"price": str(price), "currency": o.get("priceCurrency"),
                        "stock": avail or None, "offers": len(offers), "source": "jsonld"}
    return None

def from_selectors(page):
    out = {"currency": None, "offers": None, "source": "selector"}
    for key, sel in FALLBACK.items():
        try:
            out[key] = (page.locator(sel).first.text_content(timeout=10_000) or "").strip() or None
        except PWTimeout:
            out[key] = None
    return out

with sync_playwright() as p, open("prices.csv", "a", newline="") as f:
    writer = csv.writer(f)
    browser = p.chromium.launch()
    page = browser.new_page(user_agent=UA)
    for url in PRODUCTS:
        now = datetime.now(timezone.utc).isoformat(timespec="seconds")
        if not allowed(url):
            print(f"{url}  skipped (robots.txt)")
            continue
        try:
            resp = page.goto(url, wait_until="load", timeout=30_000)
        except PWTimeout:
            print(f"{url}  timeout")
            writer.writerow([now, url, None, None, None, None, "timeout"])
            continue
        status = resp.status if resp else None
        blocks = page.locator('script[type="application/ld+json"]').all_text_contents()
        row = from_jsonld(blocks) or from_selectors(page)
        print(f"{url}  {status}  {row['price']} {row['currency'] or ''}  "
              f"{row['stock']}  ({row['source']})")
        writer.writerow([now, url, status, row["price"], row["currency"],
                         row["stock"], row["source"]])
        time.sleep(DELAY_S)
    browser.close()

A few choices in there, and why:

  • The price stays a string. "49.90" turned into a float and back is how you end up with 49.900000000000006 in a report. Convert with decimal.Decimal when you compare prices.
  • waituntil="load", not "networkidle". Playwright's own docs discourage networkidle, and pages with chat widgets or analytics polling never go idle. If the store injects its JSON-LD with JavaScript after load, wait for it explicitly: page.locator('script[type="application/ld+json"]').first.waitfor(state="attached").
  • The source column. When you add store number 2, you'll immediately see which stores need hand-written selectors and which don't.
  • HTTP status in every row. A 403 or 429 is the store telling you something. Slow down or stop, don't retry harder.

Before you trust the numbers

Check the 5 products against what you see on the page, once, by hand. That's the actual test for this issue, and it catches the cases below:

  • Variants. A T-shirt in 4 sizes has 4 offers, sometimes with different prices and stock. The script takes the first offer with a price and records how many offers there were. If that number is above 1, decide which variant you're tracking (by sku in the offer) instead of trusting "first".
  • Sale prices. Some themes put the regular price in JSON-LD and show the sale price on the page (or the other way round). If they disagree on your pilot products, the visible price wins and you need the selector for that store.
  • "Stock" is usually in/out, not a quantity. schema.org has InStock, OutOfStock, LimitedAvailability, PreOrder, BackOrder and a few more. Shopify's public JSON only gives available. WooCommerce fills lowstockremaining only when the shop tracks stock for that product and it's below the shop's low-stock threshold, otherwise it's null. If the MVP needs real quantities, no public page will give you that reliably. You need the store's cooperation.
  • Price depends on who's asking. Currency and price can change with country (IP or a cookie), with VAT display settings, or with a customer login. Run the tracker from the same place every time, and note in the CSV which country it ran from if that could vary.
  • Cookie banners and bot checks. A consent overlay usually doesn't stop either method (the script reads text from the page, it doesn't click anything), but a few sites only load the product content after consent, and then both come back empty. A captcha or "verify you are human" page is a no: that store isn't a good pilot.

Etiquette, because it decides whether this keeps working

Five products once a day with 5 seconds between pages is nothing for a store. 5,000 products every hour is a different conversation. Keep the delay, send a user agent that says who you are, read robots.txt (the script does), and read the store's terms of use before you scale up. Prices are generally public facts, but the terms are what the store will point to if it blocks you.
